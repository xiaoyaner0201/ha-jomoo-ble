# ha-jomoo-ble

[English](README.md) · Apache-2.0 · 非官方 Home Assistant 自定义集成

面向 **九牧 ZS800J** 智能马桶，通过 Home Assistant Bluetooth 和支持主动连接的
BLE 代理本地控制。当前为开发预览版，不是九牧官方集成，**不宣称本集成已通过 HA 实机验收**。

**写入边界：**首版只允许完整 E2 设置匹配已验证命令记录的组合；其他组合保持只读。
不猜未知字段，不用默认值补齐参数，不让自动翻盖开关顺带重置水温、座温、风温、水压、喷嘴或自动冲水。

## 精确型号证据与开发过程

官方 **九牧智联微信小程序**的型号路由把 **237369 → ZS800J / bleProtocol0**。
相应广播使用 `JOMOO_SMART_` 系列前缀及该型号代码后缀。这里的数字是型号证据，
不是设备唯一标识，更不是 BLE 身份认证机制。

前期研究在设备所有者授权下，利用**官方微信小程序本地缓存**理解型号选择与协议行为，
随后做只读查询、实机动作和状态回读对照。这不等于验证了 macOS 微信界面能控制设备。
本仓库实现只依据协议事实及去标识的动作验收记录，代码为独立原创，不复制小程序代码。
不包含、运行也不需要厂商 JavaScript、解包私有包、缓存、账号信息或素材。

下列是此前**精确设备**证据，不能替代本集成的部署验收：

- FFE0 服务 / FFE1 通知与无响应写控制通道。
- `F3 F4` 帧头，源地址 `0x92`，马桶 `0x21`，广播 `0x00`。
- E2 状态查询、E7 滤芯查询返回通过长度和校验和检查的状态帧。
- 已在设备验证开盖、关盖、开座圈、关座圈、小冲、自动翻盖关/开。
  上盖/座圈位置及自动翻盖设置有状态回读；小冲有物理观察，不把 BLE 写成功当冲水完成。
- ZS800J 上盖/座圈位置取 **EA**，不套用 E2 或其他型号的解析。

以上不证明所有九牧型号、固件、温度/水压组合或 BLE 代理均可用。
详见[协议证据与保守门禁](docs/protocol.md)。

## 安装与配置

1. 备份 HA 配置，把完整 `custom_components/jomoo_ble`（包含 `lib`）复制到
   HA 配置对应的 `custom_components` 目录，重启 HA。独立 Python wheel 仅含协议库，不含 HA 集成。
2. 启用 HA 内置 **Bluetooth**。远程 ESPHome BLE proxy 必须允许主动连接；
   被动扫描器不能控制设备。连接由 HA 的可连接 BLE 后端路由，不直接连接代理 IP，
   本集成不单独读取代理凭证。
3. 把代理放在卫生间附近、信号稳定的位置。能看到弱广播不代表连接可靠。
   注意防水和供电安全，不把裸设备塞进马桶或靠近市电布线。
4. 先断开/关闭官方小程序。马桶同一时刻只允许**一个 BLE central**连接。
   建连可能鸣叫；默认轮询 60 秒，可在选项调为 30–3600 秒。
5. 设置 → 设备与服务 → 添加 **JOMOO BLE**。只在本地输入真实 BLE MAC，
   名称前缀默认 `JOMOO_SMART_`。`02:00:00:00:00:01` 是明确虚构的格式示例，
   不要拿它连接。macOS CoreBluetooth UUID 不是 MAC。未支持的广播型号会拒绝。
   配置过程只读查询，结束后主动断开。
6. 先与官方小程序/遥控器核对只读状态。动作**默认禁用**；有人在旁、机构无阻挡时
   再在集成选项启用。“已验证参数组合”关闭时仍禁止写入，不要为了绕过门禁修改设备设置。

仓库未假定 GitHub 地址、维护者账号或 HACS 上架。manifest 文档地址只指向 HA 蓝牙前提文档；
项目说明在本 README。公开维护者身份、项目链接及发布需另行确定。

## 实体

| 类型 | 内容 | 边界 |
| --- | --- | --- |
| Sensors | 水温/座温/风温档位，臀洗/妇洗水压档位、喷嘴位置 | 不是摄氏度；完整 E2 匹配已验证组合才输出数值。 |
| Sensor | E9 工作状态原始代码 | 不猜清洗/冲水模式名称。 |
| 诊断 Sensors | E2/E7/FA/E9 原始载荷 | 默认禁用；滤芯剩余百分比/单位尚未映射。 |
| Binary sensors | 上盖开、座圈开、上盖运动、座圈运动 | EA 实际回读，未知位置不会当作关闭。 |
| Binary sensors | 自动冲水设置、已验证参数组合 | 自动冲水只读。 |
| Switch | 自动翻盖开关 | 唯一实现的可写设置。 |
| Buttons | 开上盖、关上盖、开座圈、关座圈、小冲 | 必须先取当前状态；没有乐观更新。 |

已验证型号开座圈会同时开上盖；关座圈后上盖保持开。`0x11` 同时用于开盖/关座圈，
不是笔误。上盖已开时“开盖”直接返回当前状态，避免把已开的座圈关掉。
没有编造“冲水成功”传感器。

## 参数与连接安全

轮询、动作、关停共用锁和短时单连接。每次动作在**同一连接**里先取得新鲜 E2 与 EA，
检查位置已知、机构未运动，再校验完整 E2 参数组合。保留当前已验证组合里的全部参数，
不使用过期 HA 状态。构造 19-byte 帧时仅改动作选择器；自动翻盖仅改 `0x19` 选择器和
`0x08` 位。其余参数字节保持不变。任何其他 E2 位变化直接拒绝，不猜未知字段。

写入后再次查询，只发布设备真正返回的状态。翻盖/座圈要求到达目标且停止运动，
自动翻盖要求 E2 开关吻合；小冲只发送一次再读状态，**没有物理完成 ACK**。
失败或未确认会使实体不可用，不自动重试，也不乐观更新；报错不代表硬件一定没收到，
重试前请看现场。包括取消在内，均在 `finally` 断开；断开不确定时阻断后续连接，需重载。

协议没有事务 ID，延迟通知、顺序、设备机械保护和未回报的设置仍需实机验收。
本集成不是落座安全系统，不能代替设备保护。首版没有独立建立落座位映射，因此不发布落座实体。

## 自动化目标：联动待接入

目标是：**热水器正在出热水时禁用自动翻盖，停止出热水时恢复此前的原状态**。
开始出热水时保存实际自动翻盖状态；结束时恢复保存值，而不是一律打开。
原来就关闭的，恢复后必须仍关闭。

**目前没有连接热水器，联动待接入。**热水器通电、热水储罐很热或温度阈值都不能替代
“正在出热水”的真实信号。本仓库不含虚构热水器实体、假流量传感器或可直接用于某家庭的联动。
后续需验证真实出水/加热信号、消抖、重启与 unavailable 策略、人工覆盖，以及失败后不重复动作。

## 未支持、未宣称

不实现清洗、烘干、大冲、温度/水压/喷嘴设置、夜灯设置、激活、设备身份写入、恢复出厂、
升级/OTA、云账号登录或任意原始命令服务。看到某个状态不代表对应写入已验证。
不支持其他型号，也不混用 `5A` / `FFA0` 等不同协议。不把厂商私有包提交进仓库。

## 本地开发与验证

协议与模拟 BLE 会话测试只需 Python 标准库，不连接 HA、蓝牙、账号或生产配置：

```sh
python -m unittest discover -s tests -v
python scripts/sync_library.py --check
python scripts/check_repository.py
ruff check .
```

`check_repository.py` 对全部 Python 文件实际执行 `py_compile`、解析 JSON、检查本地 Markdown 链接和基本公开数据卫生。
CI 在 Python 3.10、3.13、3.14 重跑。`jomoo_ble` 是协议库正本；
`scripts/sync_library.py` 生成集成内字节一致的副本，修改正本后同步。

上述通过只证明离线代码/夹具行为。真实 HA config flow、BLE proxy 连接、精确设备回归仍是部署者验收门槛。
参见 [CONTRIBUTING](CONTRIBUTING.md)、[SECURITY](SECURITY.md)、[CHANGELOG](CHANGELOG.md)。
